# Data dictionary and provenance

Paths below are relative to the repository. SI GB/s = 10^9 bytes/s; GiB/s = 2^30 bytes/s; MiB/s = 2^20 bytes/s. GFLOP/s = 10^9 floating-point operations/s. A fused multiply-add counts as two operations. ns = 10^-9s; µs = 10^-6s.

## Shared record format

`data/raw/runs/*.json` in projects 1/2 wraps an exact argument vector, UTC start, subprocess duration, exit status, full stdout/stderr and parsed measurement. Every original run has a case ID and trial number; config/plan.json is the coverage specification. JSON is the source of truth; CSVs are derived. Trial numbers start at zero. No failed row is silently converted to success.

`environment-before.json`, `environment-after.json`, `environment-final.json` retain OS/kernel, hardware, cache/page metadata, compiler and Xcode versions, Python packages, tool versions, power policy, AC/battery state, VM/disk context, read-only SMART health, source hashes and explicit affinity/frequency/SMT/NUMA policies. Earlier source hashes describe that collection stage; later analysis/supplement files can legitimately differ. Exact build flags are in evidence/build.json. `AI_USE.md` separates agent checks from pending student review. Hypotheses were written before primary collection, not retrofitted to the outcome.

Summary CSVs report median, sample standard deviation (ddof=1), and count; project 3 additionally retains min/max. Error bars are trial variability, not confidence intervals. All valid trials, including anomalies, are retained. Rejected pilots are separately labeled in evidence and never pooled into accepted tables.

## Project 1

- `measurements.csv`: case_id/trial/build/kernel/dtype/n/stride/offset_elements; address_mod_128 validates alignment; working_set_bytes counts active array extents (including stride gaps), not useful bytes per call. elapsed_ns is timed repeated-batch duration; iterations and elements_per_iteration give total elements. ns_per_call=elapsed_ns/iterations; ns_per_element divides again by elements_per_iteration. gflops and gib_per_s use documented source-level operations/traffic, not physical memory traffic.
- cycles/instructions are process rusage counter deltas; pcycles counts P-core cycles. cycles_available/pcycles_available indicate support. cycles_per_element=cycles/(iterations*elements). effective_ghz=cycles/thread_cpu_ns; it is effective clock over the interval, not a fixed clock guarantee. p_core_cycle_fraction=pcycles/cycles. speedup pairs scalar and optimized ns_per_call by trial, dtype, kernel, N, stride and offset.
- AXPY: 2 FLOP and 3 scalar transfers/element; multiply: 1 and 3; stencil: 5 and 2 useful scalar transfers/interior element (spatial input reuse); dot: 2 and 2. float32/64 have 4/8B transfers. Checksum is outside the timed interval.
- `summary.csv`, `key_comparisons.csv`, `alignment_ratios.csv`, `stride_comparison.csv`, `negative_case.csv` summarize primary data. `negative_control.csv` derives 30 supplementary volatile-accumulator raw jobs; it is distinct from the partly vectorized ordinary dot.
- `bandwidth_reference.csv` parses STREAM's decimal MB/s; `compute_ceiling.csv` parses 16 independent 128-bit float32 FMAs, 128 FLOP per inner iteration, 50M iterations. `roofline.csv`: intensity=FLOP/useful bytes; bound=min(empirical compute ceiling, STREAM Copy bytes/s × intensity). This is a traffic-dependent reference, not a strict vendor peak.
- `evidence/correctness-boundaries.json`: 324 independent small boundary/stride/offset checks. Negative-control builds/compiler reports and targeted disassembly prove no vector arithmetic. `evidence/rejected-peak-pilot/` preserves the rejected 9-FMA pilot and reason.

## Project 2

- `measurements.csv`: chase rows record allocated bytes, spacing, node count, seed, loads, elapsed_ns, latency_ns=elapsed_ns/loads, real cycles/instructions, cycles_per_load, native page bytes, active_line_bytes and reference correctness. Spread address footprint differs from touched cache-line count.
- Traffic rows record read_percent, threads, useful bytes/operation counts, minimum/maximum worker time intervals, process counter totals and independent random-chain probe_latency_ns. useful_gib_per_s uses source-level 8B operations over elapsed_ns, the main probe timing window; worker_min_ns/worker_max_ns expose start/stop skew. Precomputed random index reads and write-allocate/writeback bus traffic are extra and not counted as useful bytes. Probe latency measures reads under load; it is not store persistence time.
- `intensity.csv`: useful throughput versus probe latency; illustrative required line concurrency uses a separate probe and is explicitly an approximation, not observed outstanding requests. `latency_baselines.csv` labels working-set regimes, not guaranteed isolated physical levels.
- `data/raw/counters/*`: metadata JSON, target stdout, compressed raw TOC/sample XML and complete original .trace.tar.gz. Counts are interval deltas in samples whose **leaf PC** belongs to the selected target kernel, including kernel warmup. They are not exact whole-process perf-stat totals. Per case there are 3 separate instrumented trials; do not pool them as plain timing repetitions.
- Events: L1D_CACHE_MISS_LD_NONSPEC, L1D_TLB_MISS_NONSPEC, L2_TLB_MISS_DATA, Cycles, Instructions, INST_SIMD_ALU. The latter also counts scalar FP; it is not by itself proof of vectors. `counters.csv` normalizes misses per 1,000 sampled retired instructions and joins target timing. Event names/definitions and selected template are retained.
- `followup.csv`: 18 tiny-cycle unroll controls (63/64 loads) and 15 balanced-page-offset timing rows. `followup-source-provenance.json` explains a transparent source-file rename after collection. `amat_illustration.csv` converts misses/instruction to approximate misses/load using 66 instructions/64 loads, then endpoint-calibrates an incomplete AMAT model. Its poor largest-case fit is reported.
- `evidence/hugepage.json` records the actual failed superpage request; huge-page rows are absent because unavailable, not lost.

## Project 3

- `data/raw/runs/*-meta.json`: exact FIO command, full stdout/stderr, case/trial, timing, temperature/SMART before/after, owned filename, prep flag. Adjacent `.json` is the full FIO JSON+ result with separate read/write statistics and latency histograms. `config/generated/*.fio` is the exact corresponding configuration. prep=true excludes 2 preparation jobs from performance tables.
- `measurements.csv` has **one row per active I/O direction**, so a mixed job has two rows. Aggregate iops, bandwidth_mib_s, total_io_count, combined_mean_latency_ns and actual_write_bytes repeat across those two rows; deduplicate by case_id/trial before summing group totals. direction_iops/io_count/mean_latency_ns/percentiles are direction-specific. `numjobs` records forked-process count; primary jobs use one process.
- Total lat_ns = submission plus completion; clat_ns is completion only. p50_ns/p95_ns/p99_ns/p999_ns use total latency, with latency_percentile_kind retained. Percentiles are never averaged across read/write populations. Median-of-trial percentiles differs from a percentile of pooled requests. `combined_mean_latency_ns` weights directional means by completed I/O counts.
- estimated_mean_outstanding = aggregate IOPS × combined_mean_latency_ns × 10^-9. This is Little's Law for the application request population, not directly measured controller NVMe depth. effective_depth_distribution retains FIO's iodepth_level JSON; requested depth may not be achieved.
- `tail_counts.csv` preserves each trial and expected number above p99.9 (=io_count×0.001), not an exact independently counted exceedance. Survival plot pools raw clat histogram bins separately. All six tail trials and the ~7.37ms p99.9 outlier remain present.
- `range_bytes` is a logical file span; numjobs>1 partitions the aggregate range into disjoint aligned portions. APFS placement/physical LBAs are unknown. direct=1 is F_NOCACHE, not per-I/O persistence. direct=0 appears only in the labeled buffered-cache pitfall.
- `data/raw/ledger/*.json`: reserve worst-case write bytes **before** each run; record actual completed write bytes afterward. A missing completion conservatively retains its reservation. Cumulative cap104GiB; actual53.374626GiB. read-only runs have zero test-write bytes; filesystem metadata/OS background writes are not charged as FIO payload.
- `zero_queue_baselines.csv`, `queue_curve.csv`, `parallelism.csv`, `summary.csv` are grouped derived outputs. IOPS includes reads+writes; bandwidth includes payload bytes only. Percentiles/throughput use the same run windows.
